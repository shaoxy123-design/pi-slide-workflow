# From source material to an editable presentation

Original sample material prepared for rehearsing this repository's slide workflow. It describes the workflow's design; it does not report benchmark results or promise a completion time. Use it to teach colleagues how the three roles work together.

## 1. Start with the intended outcome

A professor may want to improve an existing deck or create a new presentation from notes, reports or data. These requests need different content rules. Improving an existing deck preserves its wording, evidence, notes and slide order by default. Creating a new deck allows faithful selection, summarization and organization within the requested brief.

Both paths preserve original files. A new deck must keep claims traceable to the source and retain important qualifications. The workflow does not invent facts or data to make a slide more persuasive.

## 2. Planner

The Planner is the main agent talking with the professor. It identifies the audience, objective, required topics and useful visuals. It asks when a consequential decision is unresolved, such as a conflict between a strict slide limit and required coverage. It uses reasonable defaults for ordinary style decisions.

For a new deck, the Planner maps source evidence to claims and creates a storyboard. For an existing deck, it identifies improvements while locking protected content. It passes a concrete plan to the Executioner.

## 3. Executioner

The Executioner creates or edits a working copy using the available presentation tools. Text, tables, charts and diagrams remain native and editable. An illustration may be a separate replaceable picture.

Each topic visual is delivered as one already-assembled group or picture. A professor can move or resize it with one selection and edit native parts inside the group. Useful visuals should explain the topic; extra decoration should not crowd the content.

## 4. Reviewer

The Reviewer independently inspects the original request, sources, exported deck and evidence. For improvement, it checks that protected content remains intact. For creation, it checks that slide claims faithfully represent the source.

It also checks readability, topic visuals, editability and the actual file. Concrete problems go back to the Executioner for repair. Any revised candidate needs a fresh review tied to that file.

## 5. Delivery and demonstration

A completed run delivers an editable PowerPoint, a matching preview and a short report. A newly authored deck also includes a source map. Only the reviewed candidate is presented as final.

During a demonstration, show the plan, one visual improvement and the review result. Demonstrate editing on a disposable copy. Rehearsal helps choose a suitable example, but local runs have no automatic deadline. Prepared results can be shown when clearly labeled as rehearsal outputs.
